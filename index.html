LYN_0 Academy · Mission 02

Memory that survives.

Your agent forgets you the moment the conversation closes. This is the week of work that gives it a memory file it writes itself, the rules for deciding what goes in it, and a review that stops the file rotting from the inside.

Every session starts at zero

So you re-explain the same things. Where the invoices live. Which folder is off limits. That the client statements arrive password-protected. That you want answers in one language and code in another. You tell it once, it nods, and tomorrow it has never heard of you.

The fix is a file your agent owns: memories/MEMORY.md. It gets injected into the system prompt on every single turn, before your message. There is a hard 2,200-character budget, and that budget is the entire problem. When the file fills up, something gets squeezed out, and the file never tells you which entry lost. A stale entry does not look stale. It looks like a fact, and the agent repeats it with the same confidence as everything else in there.

What is in the week

FileWhat it does
mission.mdThe mechanism: where memory actually lives, what the budget means, and why a stale entry is worse than a missing one.
questionnaire.mdA memory inventory: what you keep re-explaining, what the agent keeps getting wrong, and what you thought was memory but is really a procedure.
files/MEMORY_TEMPLATE.mdA starter memory file written the way an agent should write it, which is not the way a person takes notes.
files/SOUL_MEMORY_BLOCK.mdThe rules block for SOUL.md: save this without asking, never save that, merge before you save when the file is nearly full.
files/skills/lyn0-memory-review/A real skill. You say "run a memory review" and it walks both files, sorts every entry into keep, demote, replace or delete, and proposes a diff. Nothing changes until you approve it.
install.pyInstalls the starter and the skill, audits what is already there, and refuses to overwrite a memory file your agent wrote. It backs up before it writes, every time.
test.mdSix checks to run in a fresh session, including the uncomfortable one: move the files, watch it forget you, put them back.

About 40 minutes the first time. Then five minutes a week, forever.

What it prints on a real store

The pack includes an audit. This is its output on a working setup, two weeks after the owner stopped tidying up:

  MEMORY.md: 7 entries, 1889/2200 chars (85%)
      [ 552] Project invoice extraction: local OCR pipeline, tesseract at C:\...   <-- too long
      [ 331] Home lab: proxmox host on 192.168.1.20, three containers ...          <-- too long
      [ 214] Client X sends statements as password-protected PDFs, password in ...
      [ 180] Standing convention: replies in Italian, code in English
      above 80%: consolidate before you save anything new

  USER.md: 5 entries, 1205/1375 chars (87%)
      [ 353] Runs a two-person studio, works from home most of the week ...        <-- too long

Two entries eating a fifth of the budget each, and the file already over eighty percent. That is what memory rot looks like before anyone notices it.
